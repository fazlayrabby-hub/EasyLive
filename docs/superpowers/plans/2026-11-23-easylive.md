# EasyLive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-window Windows app that detects PC + internet capability, picks stream settings itself, and live-streams a screen/window with audio to YouTube or Facebook over RTMPS.

**Architecture:** `EasyLive.Core` holds all decision logic as pure, unit-tested code (planning, adaptation, key store, blank-frame detection) plus thin adapters around Windows/FFmpeg (hardware detection, capture, audio, encode/send). `EasyLive.App` is a WPF shell with one screen. Adapters sit behind interfaces so logic is tested without a GPU or network.

**Tech Stack:** C# / .NET 8, WPF, xUnit, Windows Graphics Capture (WinRT), NAudio (WASAPI), FFmpeg LGPL shared build via FFmpeg.AutoGen, OpenH264, MediaMTX (local RTMP test sink).

**Spec:** `docs/superpowers/specs/2026-11-23-easylive-design.md`

## Global Constraints
- Windows 10 2004+/11 only; target framework `net8.0-windows10.0.19041.0`.
- Whole build LGPL-clean: **no x264/GPL**; FFmpeg LGPL shared build, dynamically linked; CPU fallback = OpenH264, capped at 720p30.
- Resolution fixed per session; only bitrate adapts live (brief re-init with new keyframe allowed as last resort, never a silent freeze).
- Platform server URLs built in: YouTube `rtmps://a.rtmps.youtube.com:443/live2`, Facebook `rtmps://live-api-s.facebook.com:443/rtmp/`; user supplies only the key.
- Stream keys stored encrypted with Windows DPAPI (CurrentUser).
- Upload probe max ~8 s, never sends data to the real ingest; start bitrate ≈ 60% of measured upload.
- Auto-reconnect up to 2 minutes, then stop and explain. Black capture >3 s → warn. Single-instance app.
- UI: one window, large **Go Live** button, plain-language status, Stop button; no bitrate/encoder/resolution controls.
- Ship licence texts + third-party notices. Hardware validation required on Intel Iris Xe and the AMD PC; NVENC marked untested.
- Commit steps are local commits only; pushing needs the user's approval.

## Review Focus
1. **No microphone present/unplugged mid-stream:** stream continues with system audio only, status says mic is off (Task 8).
2. **Stream key pasted with spaces/newline or wrong platform's key:** trimmed; empty/garbage rejected with plain message (Task 6).
3. **Captured window closed or minimized mid-stream:** user is told in plain words; stream does not freeze silently (Tasks 7, 10).
4. **Offline / speed server unreachable during probe:** "No internet connection" message, no crash, no stream start (Task 4).
5. **Hybrid-GPU laptop (iGPU + dGPU):** encoder preference uses the adapter that is actually capturing; unknown vendor falls back safely (Task 3).
